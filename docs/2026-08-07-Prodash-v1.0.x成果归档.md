## 二、架构总览

```
浏览器 H5（后端同域托管 :8787）
    ↓ HTTP API（无登录，单用户 demo）
Node 后端（Express + MySQL）
    ├── tasks / time_events / reports / report_extra
    ├── 21:00 调度（REPORT_CRON，当天已发布则跳过）
    ├── Dify Workflow（只产出日报文本，输入已预格式化用时）
    └── 发布器抽象 publishReport()
        └── DwsCliPublisher（dws CLI → 钉钉知识库「日报」文档）
```

- 数据口径：`今日完成 = completedAt ∈ [服务器本地当天00:00, 次日00:00)`；运行中/跨日会话按生成时刻 asOf 截断
- 机制 b：保存补充内容后自动重生成并**覆盖同一文档**（docNodeId 不变）
- 生产化线索：发布器接口抽象（可换企业应用 OpenAPI 实现）、report 状态机（draft/published/publish_failed + 补发）、event 级计时明细（跨日切分/周月趋势直接可算）

## 四、真实联调成果（钉钉侧）

1. **多组织访问问题**：为隔离测试新建的独立钉钉组织「ai日报应用测试」中创建的知识库，被当前 dws profile（亿维融智）跨组织拦截（`forbidden.accessDenied`）。解决：`dws auth login` 用目标组织账号登录后 profile 出现第二个组织即可访问。已固化进预配文档「多组织/隔离组织前置检查」。
2. **知识库归档**：自动日报已真实发布到「测试使用」知识库 → `（1.0.1）` 文件夹（示例：日报 2026-08-06，含随机种子任务的完成时间与双轨用时）。
3. **用时标注修正**：服务端把 humanMs/agentMs 预格式化为可读文本（`totalTime` 合计），提示词强制 LLM 直接引用不换算——纯 Agent 任务用时从"不足 1 分钟"误标修正为准确值（如 15/35 分钟）。
4. **Dify 工作流**：应用「Prodash webapp」已按新变量契约更新（`time_summary`、每项 `humanMs/agentMs/humanTime/agentTime/totalTime`）并发布。

## 五、关键工程决策（复盘沉淀）

| 决策 | 结论 | 理由 |
|---|---|---|
| 数据架构 | DB 为主，前端直连 API，localStorage 清零 | P0 自动生成依赖数据在服务端，浏览器不可信 |
| 版本定位 | demo 特权原型（以生产姿势编写，7 条生产化线索） | 明确与生产化边界，文档留钩子 |
| 隔离组织 | 优先同组织内隔离；独立组织必须先 `dws auth login` 目标组织账号 + `--profile` pin | 钉钉跨组织数据硬隔离，凭据组织级绑定 |
| 工具职责 | dify-agent（Dify 工作区）与 dws（钉钉组织）凭据域分离 | 本次"找不到组织"系 dws 多组织问题，与 dify-agent 无关 |
| LLM 用时 | 服务端预格式化 + 提示词强制引用 | 毫秒原始值被 LLM 换算时幻觉（曾把 15 分钟写成 8 小时） |

## 六、v1.1.0 钉钉待办同步（本期新增）

### 6.1 背景与定位

用户在调研中发现钉钉内置「待办」完整可用（`dws todo` 全命令族实测），定位为**领导分发任务的载体**。核心诉求：自动日报是硬需求，本集成让「今日待办数据」更完整——领导任务也进日报。同步方向为**单向导入 + 完成回写**（双向完成状态同步；个人任务不上钉钉，钉钉任务不可从 prodash 删除）。

### 6.2 架构

```
钉钉待办（dws todo，来源组织由 DINGTALK_TODO_PROFILE 配置）
        ↓ execFile(node.exe, dws.js, args)
Node 后端（server/todoSync/）
    ├── DwsTodoClient      读：todo +get-my-tasks --role-types executor；写：todo task done（--status true/false）
    ├── TodoSyncService    upsert 入库 + 强制四象限 + 完成状态回写 + 钉钉侧删除软删本地
    └── routes             POST /api/todo-sync（手动触发）、GET /api/todo-sync（同步状态）
            ↑ 调度：server/scheduler.js 每 30 分钟轮询（DINGTALK_TODO_SYNC_CRON）
MySQL tasks 表（新增 6 列：dingtalk_task_id / source / source_leader / due_time / sync_origin / sync_writeback）
    └── 前端照常读 /api/tasks；日报照常走 /api/reports（含 source/sourceLeader 字段）
```

### 6.3 关键设计

- **导入口径**：所有指派给我执行的任务（`--role-types executor`），含考勤等系统任务（`bizTag: certify_todo`）
- **四象限锁定**：钉钉任务强制「重要·紧急」；标题/象限/删除三重锁定（前端禁用 + 后端 403 双保险，PATCH `status='deleted'` 绕过亦被堵）
- **完成回写**：prodash 勾选/取消即时回写钉钉（`todo task done --status true|false` 双向对称）；失败 → `sync_writeback='pending'` 无限重试 + 前端「同步失败待重试」标记；pending 不回退（轮询不得把本地已完成改回）
- **软删**：钉钉侧删除任务 → 连续 2 次轮询确认后本地软删
- **性能**：节流（<2 分钟跳过）、详情并发限 5（p-limit）、后端异步
- **组织隔离**：`.env` 显式 `DINGTALK_TODO_PROFILE`（corpId:userId），未配置 fail-fast 报错，杜绝跨组织访问
- **日报口径**：`completed_at` 优先本地勾选时刻，钉钉侧完成以同步发现时刻补写；日报输出带 `source`/`sourceLeader` 统计

### 6.4 验证证据

- **自动化测试**：296/296 全绿（27 个测试文件）
- **质量门禁**：11 个任务逐个 TDD + Oracle 逐任务审查 + 最终整分支审查（2 Important / 4 Minor 全部修复）+ 修复 wave 后 scoped re-review 确认 READY TO MERGE
- **真实联调（钉钉侧）**：`POST /api/todo-sync` 对真实 dws CLI 返回 200（`{"imported":0,"updated":0,"softDeleted":0,"writeback":{...}}`）
- **生产 bug 修复**：联调暴露 2 个 dws CLI 契约问题并修复——`--size/--page`（非 `--page-size/--page-num`）、`--status` 为布尔 `true/false`（非 `active/completed` 字符串）

### 6.5 生产化线索

| # | 线索 | 位置 | 生产化动作 |
|---|---|---|---|
| ① | 完成时间缺失 | 钉钉 `finishTime=0` | 企业应用 OpenAPI 侧核实完成时刻，或保持本地口径 |
| ② | 回写重试队列 | `sync_writeback` | 加重试退避与告警 |
| ③ | 组织配置 | `DINGTALK_TODO_PROFILE` | 多账号选择策略收敛到统一配置面 |
| ④ | 同步互斥 | in-flight 标记 | 生产化换分布式锁/队列 |
