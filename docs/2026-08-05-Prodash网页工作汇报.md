### 项目简介

一个深色主题的个人效率网页，顶部有四个功能页签：**待办 / 番茄钟 / 笔记 / 记账**。第一版把「待办」做成完整可用，另外三个先放"敬请期待"占位页，后续逐个补齐。

待办功能采用**艾森豪威尔四象限**：添加任务时用「重要？」「紧急？」两个开关，自动归入四个象限格子（重要紧急=立即做 / 重要不紧急=计划做 / 不重要紧急=快速处理 / 不重要不紧急=尽量少做），支持**列表 / 四象限双视图**切换，数据存在浏览器本地，刷新不丢失。

## 二、走的完整流程（重点）

这次最大的收获不是网页本身，而是完整走了一遍真实项目的开发流程：

| 阶段 | 做了什么 |
|------|---------|
| 1. 需求澄清 | 通过一问一答明确：零基础、想要能用/能分享、选实用小工具、定「工作台框架 + 先做待办」、深色主题、React 技术栈 |
| 2. 方案选择 | 三选一：标签页工作台（推荐）/ 路由多页面 / 只做待办，定了**标签页工作台**方案 |
| 3. 设计文档 | 逐节确认 5 个部分：架构、组件结构、数据模型、错误处理、测试部署，写入 `docs/superpowers/specs/` |
| 4. 实现计划 | 用 writing-plans 技能拆成 **8 个 TDD 任务**（先写测试→看失败→实现→看通过→提交），写入 `docs/superpowers/plans/` |
| 5. 子代理执行 | 每个任务派独立子代理实现，主代理逐任务审查，UI 视觉交给设计师代理 |
| 6. 验收部署 | 全量测试 + 构建 + 本地验收 → GitHub Actions 自动部署到 GitHub Pages |

## 三、技术成果

- **技术栈**：React 18 + Vite 8 + Vitest 4 + React Testing Library，纯前端，无后端
- **数据**：localStorage 持久化，读写都做了异常兜底，任何错误不崩页面
- **代码**：8 个功能提交，组件按职责拆分（App 外壳 / 待办 / 四象限 / 通用钩子）
- **测试**：24 个自动化测试全部通过（持久化 7 + 待办列表 5 + 四象限 5 + 外壳 3 + 验收补充 4）
- **视觉**：深色主题、四象限专属配色、手机窄屏响应式
- **部署**：GitHub Actions 自动构建发布，推代码即上线

## 四、踩过的坑（真实成长）

1. **工具缺失**：brainstorming 流程要求的 writing-plans 技能本机没装 → 用技能市场一条命令装好再继续
2. **Git 身份未配置**：提交被拦 → 用临时身份参数逐次提交，不动全局配置
3. **GitHub Pages 未启用**：工作流在 Setup Pages 步骤失败 → 在仓库设置里把 Source 切到 GitHub Actions，重新推送后部署成功
4. **测试环境差异**：jsdom 可能不支持 `crypto.randomUUID` → 在测试配置里做了兜底
5. **验收测试误报**：四象限组合测试首轮失败，最后定位是测试辅助函数缺陷，应用本身没问题——这提醒我"测试报错要先怀疑测试"

## 五、关键收获

- **AI 不是替代我，是放大我**：我不会写代码，但能通过"说需求→看方案→确认设计→让 AI 实现→验收"的方式做出能上线的产品
- **先想清楚再动手**：提前做需求澄清和设计，比边写边改省了太多返工

- **分阶段不贪多**：四个工具只先做待办，否则大概率烂尾
