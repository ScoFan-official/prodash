# Prodash v1.1.3 前端 UI 升级设计文档

## 1. 背景与问题

当前 Prodash（个人效率工作台）前端使用 React + Vite，样式为纯手写全局 CSS（`theme.css` + `components.css`，约 1424 行）。在 v1.1.3 中集中解决以下设计问题：

- **信息密度过载**：`TodoItem` 把 checkbox、标题、最多 3 个标签、象限标签、两条独立计时轨道（标签+状态+按钮+时长）、删除按钮塞进同一行，桌面端拥挤，移动端严重换行。
- **设计系统缺失**：无统一按钮/输入框/卡片/表格/空状态 primitive；存在硬编码色值（`#2f6fed`、非existent `--muted`）；危险悬停样式误伤计时按钮。
- **导航隐喻混淆**：顶部 App 级 Tab（待办/日报/笔记/Token流水）与待办页内视图切换（列表/四象限/统计）都是 `role="tablist"`，层级不清。
- **原生控件未样式化**：日报页的 `<select>`、`<table>`、同步待办按钮等仍使用浏览器默认外观，在深色主题中突兀。
- **反馈与空状态薄弱**：错误以红色段落堆叠在列表上方；加载为纯文本「加载中…」；占位 Tab 仅显示「敬请期待」。
- **响应式断点单一**：仅 640px 一个断点，无 tablet 适配；统计排行、日报历史表格在小屏下可能溢出。
- **可访问性不足**：焦点环不统一，部分按钮仅靠 `aria-label`，键盘箭头导航缺失。

## 2. 目标与非目标

### 2.1 目标

1. 建立一套可维护的深色主题设计系统（tokens + primitives + components）。
2. 解决任务行信息过载，让待办、四象限、统计在桌面和移动端都可读。
3. 区分「App 导航 Tab」与「页面视图切换」两种控件，消除层级混淆。
4. 补齐日报页缺失的样式，统一 Select、Table、Checkbox、Button 外观。
5. 引入轻量 headless UI primitives（Radix）处理焦点、键盘、弹层、工具提示。
6. 提升响应式体验，新增 768px、1024px 断点。
7. 改善空状态、错误提示、加载状态。
8. 版本号升级到 `v1.1.3`（`package.json` 与 README 同步）。
   > 注：本次升级虽涉及组件与样式架构调整，但对外功能契约（API、数据模型、页面路由）保持不变，因此按 patch 版本处理；设计系统建设是本次 patch 的核心目标。

### 2.2 非目标

- 不引入 Tailwind CSS 或 shadcn/ui 完整组件库（保持依赖轻量）。
- 不改业务数据模型与后端 API 契约。
- 不新增功能页面（笔记/Token 流水仍为占位，但给出明确引导）。
- 不做品牌级插画或动效大片；以可用性、一致性、可读性优先。

## 3. 设计原则

- **深色专业感**：延续 `#0B0D12` 深色背景，表面层级通过 `#14171F` / `#1A1E28` 区分，强调色保持冷静蓝 `#7FB8FF`，低噪、聚焦。
- **结构即信息**：导航层级、视图切换、任务元信息通过结构和间距表达，减少装饰性数字/线条。
- **一行一意图**：任务行的第一行只做「识别与标记完成」，计时与操作放在第二行，避免同一行承担多个动作。
- **渐进增强**：Radix primitives 负责交互无障碍与焦点管理，样式完全由项目 CSS 控制，保持视觉独特性。
- **响应式优先**：组件在默认移动端布局下工作，桌面端通过断点扩展为横向。

## 5. CSS 架构

拆分为 4 个文件，全部在 `src/main.jsx` 按顺序引入：

1. `src/styles/tokens.css` — 只放 CSS 自定义属性，无实际选择器。
2. `src/styles/base.css` — `*`, `html`, `body`, 表单元素基础样式，滚动条美化。
3. `src/styles/primitives.css` — 原子组件：`.btn`, `.input`, `.select`, `.checkbox`, `.badge`, `.card`, `.dialog`, `.tabs`, `.segmented`, `.tooltip`, `.banner`, `.empty-state`, `.skeleton`。
4. `src/styles/components.css` — 业务组件：`.app-shell`, `.todo-view`, `.todo-item`, `.quadrant-view`, `.time-stats`, `.report-view`, `.active-timers-bar`, `.task-timer-controls`。

### 5.1 命名约定

- BEM-like：`.component`, `.component__element`, `.component--modifier`。
- Primitive 用单一名词：`.btn`, `.btn--danger`, `.card`。
- 状态类用 `is-` / `has-` 前缀：`.is-active`, `.is-disabled`, `.has-error`。
- 不再使用 `button[aria-label*="停止"]` 等脆弱属性选择器。

## 6. 组件架构

### 6.1 新增/重构 primitive 组件

位于 `src/components/primitives/`：

| 组件 | 说明 |
|------|------|
| `Button.jsx` | 支持 `variant`（default/ghost/outline/danger）、`size`（sm/md/lg）、`isLoading`、`disabled`；使用原生 `<button>`， Radix 不必要。 |
| `IconButton.jsx` | 圆形图标按钮，内置 `<Tooltip>` 包装。 |
| `Badge.jsx` | 象限/状态徽章。 |
| `Card.jsx` | 统一卡片容器。 |
| `Checkbox.jsx` | 基于 `@radix-ui/react-checkbox`，自定义勾选样式。 |
| `Select.jsx` | 基于 `@radix-ui/react-select`，深色下拉。 |
| `Dialog.jsx` | 基于 `@radix-ui/react-dialog`，用于删除确认、发布预览。 |
| `Tooltip.jsx` | 基于 `@radix-ui/react-tooltip`，图标按钮释义。 |
| `Banner.jsx` | 顶部错误/成功/警告横幅，带关闭与重试。 |
| `EmptyState.jsx` | 空状态：图标 + 标题 + 描述 + 可选操作。 |
| `Skeleton.jsx` | 加载占位。 |
| `SegmentedControl.jsx` | 视图切换组件（替代第二层 tablist），基于 Radix `Tabs`，提供左右箭头键盘导航。 |

### 6.2 新增/重构业务组件

| 组件 | 改动 |
|------|------|
| `AppShell.jsx` | 顶部导航改为 App 级 `<nav>` 按钮组，使用 `aria-current="page"` 标识当前页；不再使用 Radix Tabs（避免跨页面导航误用 tab 语义）。 |
| `TodoView.jsx` | 用 `SegmentedControl` 替代 `TodoViewToggle`；集成 `Banner` 错误提示；使用 `Skeleton` 加载。 |
| `TodoItem.jsx` | 改为两行结构：第一行 checkbox + 标题 + 象限 badge + 删除；第二行双轨计时控件。 |
| `TaskTimerControls.jsx` | 每条轨道显示：状态点 + 轨道标签 + 已计时 + 开始/暂停/停止按钮组；小屏垂直堆叠。 |
| `TodoInput.jsx` | 统一使用 `Input` + `Select` + `Button` primitives，清晰的重要性/紧急性切换。 |
| `QuadrantView.jsx` / `QuadrantCell.jsx` | 2×2 网格保留，但 header 更克制，卡片内部使用 `Card` primitive，空状态用 `EmptyState`。 |
| `TimeStatsView.jsx` | 统计卡片使用 `Card`；排行与分类使用统一列表/条形；SVG donut 保留但配色使用 token。 |
| `ActiveTimersBar.jsx` | 顶部状态条使用 `Card` + 折叠动画，轨道标签更醒目。 |
| `ReportView.jsx` | 日期选择器使用 `Select`；补充内容使用统一输入框；结果卡片化；历史表格使用 styled table。 |
| `ReportHistory.jsx` | 表格带横向滚动容器、统一按钮样式、状态 badge。 |
| `PlaceholderView.jsx` | 移除；未实现 Tab 改为导航中的禁用态条目，不再渲染占位页面。 |

## 7. 页面级设计

### 7.1 待办页（Tab: 待办）

结构从上至下：

1. **Banner 区域**：全局错误/成功提示，可关闭。
2. **ActiveTimersBar**：折叠状态显示「N 个轨道运行中 ▼」，展开显示每条轨道卡片（任务名 + 轨道类型 + 时长 + 跳转/暂停）。
3. **SegmentedControl**：列表 / 四象限 / 统计。
4. **SyncRow**：「同步钉钉待办」使用 `.btn--ghost` 样式，与主操作区分。
5. **TodoInput**：卡片容器，一行内：标题输入 + 重要 switch + 紧急 switch + 添加按钮。
6. **视图内容**：
   - **列表**：`TodoItem` 列表，每项两行。
   - **四象限**：2×2 网格，header 仅显示象限名 + 任务数，卡片内任务列表。
   - **统计**：3 个统计卡 + 任务排行 + 分类占比 + 象限分布 + Agent 效率。

### 7.2 日报页（Tab: 日报）

结构从上至下：

1. **DateSelector**：使用 `Select` 选择日期 + 左右箭头切换 + 「今天」按钮。
2. **SourceSummary**：卡片展示当天任务与时长摘要。
3. **ExtraInput**：4 个字段（临时工作、会议、风险、明日计划），每项一行 label + textarea。
4. **ActionBar**：生成日报、复制结果、补发/发布按钮，使用 `.btn` + `.btn--outline` 组合。
5. **ReportResult**：结果卡片，内部 `<pre>` 保留但带样式化滚动条；生成中显示 `Skeleton`。
6. **ReportHistory**：独立卡片，表格带横向滚动，状态列用 `Badge`。

### 7.3 占位 Tab（笔记 / Token流水）

主导航中的「笔记」「Token流水」改为**禁用态**：

- 视觉：灰显文字 + `即将上线` 小 badge。
- 行为：不可点击，hover 显示 Tooltip「该功能将在后续版本开放」。
- 不再渲染独立占位页，避免用户进入空页面。

这样既能保持导航结构稳定，又避免空页面带来的困惑。

## 8. 响应式策略

新增断点：

| 断点 | 目标 |
|------|------|
| 默认（< 640px） | 移动端：任务行垂直堆叠、四象限 2×2 单列流、统计卡片单列、日报表单全宽。 |
| `sm: 640px` | 任务行第二行可横向排列双轨；四象限恢复 2×2。 |
| `md: 768px` | 列表视图任务行可完全横向（标题与计时在同一行）；统计卡片 2 列。 |
| `lg: 1024px` | 日报页可左右分栏（输入/结果 vs 历史）；统计卡片 3 列。 |

## 9. 可访问性

- 所有交互元素有可见焦点环（`--focus-ring`）。
- App 导航使用 `<nav>` + 按钮 + `aria-current="page"`。
- 页面内视图切换（`SegmentedControl`）使用 Radix Tabs 提供键盘左右箭头导航。
- Checkbox、Select、Dialog 使用 Radix 默认无障碍行为。
- 按钮文本优先，图标按钮必须带 tooltip 与 aria-label。
- 错误信息通过 `role="alert"` 的 `Banner` 播报。
- 支持 `prefers-reduced-motion`：关闭悬停/折叠动画。

## 11. 迁移计划

按**分阶段迁移**执行，保留旧样式作为 fallback，逐步替换，每阶段可独立验证：

1. **搭建设计系统基础（零破坏）**
   - 创建 `tokens.css`、`base.css`、`primitives.css`。
   - 安装 Radix、classnames、lucide-react。
   - 更新 `main.jsx` 引入新 CSS；**保留原 `theme.css` 和 `components.css` 引入顺序在最后**，作为未迁移组件的兜底。
2. **实现 primitive 组件**
   - 在 `src/components/primitives/` 中新增 Button、IconButton、Badge、Card、Checkbox、Select、Dialog、Tooltip、Banner、EmptyState、Skeleton、SegmentedControl。
   - 每个 primitive 在独立页面或 Story-like 临时路由中验证视觉与交互。
3. **迁移业务组件（小步快跑）**
   - 先改 `AppShell`（nav + 禁用态占位 Tab）。
   - 再改 `TodoView` + `TodoItem` + `TaskTimerControls`。
   - 再改 `QuadrantView` / `QuadrantCell` + `TimeStatsView`。
   - 最后改 `ReportView` + `ReportHistory`。
   - 每改完一个业务组件，就在 `components.css` 中删除对应旧样式；若新样式不完整，旧样式仍兜底。
4. **清理旧 CSS**
   - 确认所有业务组件已迁移后，删除 `theme.css` 和 `components.css` 中已被 tokens/primitives 覆盖的重复定义。
   - 最终移除旧文件引入（如确认无遗漏）。
5. **统一测试与验证**
   - 跑通 `npm test`。
   - 手动走查：待办增删改、计时开始/暂停/停止、四象限视图、统计视图、日报生成/复制/补发、响应式、键盘导航。
6. **版本与文档**
   - `package.json` 升级到 `1.1.3`。
   - README 版本历史追加 v1.1.3 记录。

## 12. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 全局 CSS 重构可能破坏现有样式 | 分文件逐步替换，每步在浏览器验证；保留旧 `components.css` 作为基线直到新样式稳定。 |
| Radix Select/Dialog 深色主题需要大量覆盖 | 所有样式完全自控，不依赖 Radix 默认主题；提供 wrapper 组件统一覆盖。 |
| 任务行两行结构在旧数据/长标题下异常 | 测试超长标题、无计时任务、已完成任务等边界。 |
| 版本号与 README 不一致 | 升级时同步 package.json 与 README。 |

## 13. 验证标准

- `npm run build` 无错误，产物大小可接受。
- `npm test` 通过（如现有测试依赖类名，同步更新测试）。
- 手动走查通过待办、四象限、统计、日报四个主场景。
- 在 390px、768px、1024px、1280px 宽度下布局无溢出、无遮挡。
- Tab/Shift+Tab 焦点顺序合理，Enter/Space 可激活主要按钮。
