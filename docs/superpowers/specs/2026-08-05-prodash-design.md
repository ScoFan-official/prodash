# 个人效率工作台 设计文档

- 日期：2026-08-05
- 状态：已获用户逐节确认

## 1. 背景与目标

使用者是一名几乎零编程基础的 AI 工具实习生，希望通过本项目：
- 完整走一遍「用 AI 工具开发网页」的流程；
- 做出一个自己真的会用的工具；
- 部署到网上，有网址可以分享给朋友。

## 2. 范围

**第一版（本次实现）：**
- 效率工作台外壳：标题栏 + Tab 栏（待办 / 番茄钟 / 笔记 / 记账）
- 完整可用的「待办清单」功能：
  - 列表视图 + 四象限视图双视图切换
  - 添加时通过「重要？」「紧急？」两个开关设定，自动归入对应象限
- 其余三个 Tab 显示"敬请期待"占位页
- 深色主题、移动端可用
- 部署到 GitHub Pages，生成可分享网址

**不在第一版范围：**
- AI 自然语言任务录入（见第 12 节路线图）
- 番茄钟、笔记、记账的真实功能
- 用户账号、云同步、多人协作
- 后端服务、数据库

## 3. 技术栈

- React 18 + Vite（JavaScript，不使用 TypeScript）
- 纯前端单页应用，无后端
- 数据持久化：浏览器 localStorage
- 测试：Vitest + React Testing Library
- 部署：GitHub Pages

## 4. 架构

单页应用。App 组件作为外壳，持有 Tab 选中状态（useState），根据当前 Tab 渲染对应组件：

```
App（外壳：标题 + Tab 栏 + 内容区）
├── Tab 状态：useState，值为 "todo" | "timer" | "notes" | "expenses"
├── 内容区：
│   ├── Tab === "todo"     → TodoView（完整功能）
│   └── 其他 Tab           → PlaceholderView（"敬请期待"）
```

- 页面不刷新，Tab 切换只换组件。
- 未来新增工具 = 新建组件 + Tab 栏加选项 + 内容区分支，不改动已有工具代码。

## 5. 组件结构

```
src/
├── App.jsx              # 外壳：标题、Tab 栏、控制显示哪个组件
├── main.jsx             # Vite 入口（标准结构）
├── components/
│   ├── TodoView.jsx     # 待办视图（第一版唯一完整功能）
│   │   ├── TodoViewToggle   # 视图切换：列表 / 四象限
│   │   ├── TodoInput        # 输入框 + 「重要？」「紧急？」两个开关 + 「添加」按钮
│   │   ├── TodoList         # 列表视图：待办列表容器
│   │   ├── TodoItem         # 单个待办：勾选框 + 文字 + 象限标记 + 删除按钮
│   │   ├── QuadrantView     # 四象限视图：2x2 格子布局
│   │   └── QuadrantCell     # 单个象限格子（展示该象限内的待办，支持勾选/删除）
│   └── PlaceholderView.jsx  # 占位页（三个未实现工具共用）
├── hooks/
│   └── useLocalStorage.js   # 读取/写入 localStorage 的通用钩子
└── styles/              # 深色主题样式
```

四象限定义（由重要/紧急两个布尔值推导，数据中不单独存象限）：

| 象限 | important | urgent | 建议处理 |
|------|-----------|--------|---------|
| 重要·紧急 | true | true | 立即做 |
| 重要·不紧急 | true | false | 计划做 |
| 不重要·紧急 | false | true | 快速处理/委托 |
| 不重要·不紧急 | false | false | 尽量少做/删除 |

职责划分：
- TodoView 只管待办逻辑，不碰 Tab 逻辑；
- App 只管框架，不碰待办逻辑；
- TodoViewToggle / QuadrantView / QuadrantCell 只负责展示与交互，象限归属由数据驱动（important + urgent 组合）；
- useLocalStorage 为通用钩子，输入 key 与默认值，自动完成读与写，供后续工具复用。

## 6. 数据模型

单个待办：

```js
{
  id: "唯一编号",          // 生成方式：crypto.randomUUID()
  text: "待办文字",
  done: false,             // true = 已完成
  important: false,        // true = 重要
  urgent: false,           // true = 紧急
  createdAt: "ISO 时间字符串"
}
```

象限由 `important` + `urgent` 组合推导（见第 5 节表格），不单独存储字段——为将来 AI 评估象限时只需填入这两个布尔值。

localStorage 存储（key：`prodash.todos.v1`）：

```js
[待办1, 待办2, 待办3, ...]
```

key 中带版本号 `v1`，为将来数据结构升级预留空间（如 v2 加入 deadline 字段）。

## 7. 数据流

- 页面加载：从 localStorage 读取 `prodash.todos.v1`，读不到或解析失败则视为空列表。
- 添加：输入文字 → 按需打开「重要？」「紧急？」开关 → 点「添加」→ 生成新待办（含象限字段）→ 插入列表 → 写回 localStorage。
- 勾选：点勾选框 → 该条 `done` 翻转 → 更新列表 → 写回 localStorage。
- 删除：点删除按钮 → 移除该条 → 写回 localStorage。
- 视图切换：列表 / 四象限互不影响数据，只改变展示方式；四象限视图中每条待办按 `important`/`urgent` 归入对应格子。

规则：用户每次操作，state 更新后立刻写回 localStorage，保证刷新/关闭浏览器不丢数据。

## 8. 错误处理与边界情况

| 情况 | 处理方式 |
|------|---------|
| 输入框为空或全为空格 | 不允许添加，按钮不产生空待办 |
| 两个象限开关均未选择 | 正常归入「不重要·不紧急」象限，不视为错误 |
| localStorage 读取失败 | 捕获异常，按空列表处理，页面照常可用 |
| localStorage 写入失败（隐私模式/空间满） | 捕获异常，页面提示"保存失败，数据可能不会留存"，不崩溃 |
| 刷新页面 | 从 localStorage 恢复数据 |
| 手机窄屏 | Tab 栏、输入框与四象限格子响应式适配（格子在手机上改为两行两列堆叠） |

原则：任何一步出错都不能让整个页面崩溃。

## 10. 测试与验证

**自动化测试（Vitest + React Testing Library）：**
- 添加待办 → 列表出现对应文字
- 勾选待办 → 呈现已完成状态
- 删除待办 → 从列表消失
- 打开「重要」「紧急」开关添加 → 在四象限视图的「重要·紧急」格中出现
- 默认添加（开关均不选）→ 四象限视图归入「不重要·不紧急」
- 视图切换（列表 / 四象限）不改变数据
- 写入后能正确读回

**手动验收清单：**
1. 打开网址，深色工作台，默认停靠待办页
2. 添加/勾选/删除待办均正常
3. 添加时打开重要/紧急开关，能在四象限视图对应格子中看到该待办
4. 列表与四象限视图来回切换，数据一致
5. 刷新页面，数据仍在
6. 切换另外三个 Tab，显示"敬请期待"，切回后待办数据未变
7. 手机打开同一网址，布局不破
8. 网址可发给朋友正常打开

## 11. 部署

1. 本地 `npm run build` 构建通过
2. 推送到 GitHub 仓库
3. 开启 GitHub Pages（Vite 项目需配置 base 路径）
4. 打开生成的网址，按手动验收清单验收

## 12. 未来路线图

按顺序追加到工作台，每个工具一个迭代周期：
1. 待办增强：AI 自然语言任务录入——用户用一句话描述要干的事，内嵌 AI Agent 就缺失细节（如 Deadline）向用户追问确认，确认后由 AI 自动评估重要性与紧急性，填入 `important`/`urgent` 字段（数据模型无需改动；若引入 Deadline，则升级 key 至 `prodash.todos.v2`）
2. 番茄钟（时间管理）
3. 笔记工具
4. 记账工具

扩展方式固定为：新增独立组件 + Tab 栏加选项，复用 useLocalStorage。
