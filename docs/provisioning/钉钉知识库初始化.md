# 钉钉知识库初始化（一次性预配）

- 日期：2026-08-06
- 适用范围：真实发布（`PUBLISHER=dws`）前的一次性预配；演示 / mock 阶段（`PUBLISHER=mock`）无需执行
- 关联决策：见 [2026-08-06-Prodash-v1.0.0决策清单.md](../2026-08-06-Prodash-v1.0.0决策清单.md) 第六节「钉钉知识库预配（一次性）」
- 产出：`DINGTALK_WIKI_WS_ID` 与 `DINGTALK_WIKI_FOLDER_ID` 两个 ID

> **严禁编造 ID**：WS_ID / FOLDER_ID 必须从 dws 命令的实际返回中提取，不得臆造。

---

## 前置条件

- 宿主机（运行后端的那台笔记本）已安装 **dws CLI** 并已登录，个人 token 有效（可先执行 `dws profile list` 确认）。
- 本手册所有命令**需按当前 dws 版本核对**：dws 各版本命令名 / 参数可能不同，一律以本机 `dws <子命令> --help` 的实际输出为准，下文命令仅作参考写法。
- 后端代码已有启动警告：`PUBLISHER=dws` 但 `DINGTALK_WIKI_WS_ID` 为空时，启动会打印 warn（见「步骤⑤」）。

---

## Dify 工作流应用变量配置

日报正文由 Dify 工作流应用生成，**开始节点输入变量与结束节点输出变量需按 README「Dify 工作流变量契约」配置**（字段名以代码 `server/services/reportService.js` 的 `buildDifyInputs` 为准）：[README.md](../../README.md#dify-工作流变量契约)。

- 用 dify-agent 创建 / 更新「日报助手」工作流应用后，在 Dify 控制台按契约核对：
  - **开始节点**：配置 7 个输入变量 `report_date` / `completed_tasks` / `pending_tasks` / `extra_work` / `risks` / `tomorrow_plan` / `time_summary`，全部为 string 类型；
  - **结束节点**：输出变量配置为 `report`（string，日报正文）。
- **与 0.2.x 阶段旧工作流的差异**（沿用旧工作流需更新，否则 Dify 会因缺变量 / 取不到 `report` 报错）：
  - **新增 `time_summary`** 输入变量（当日双轨总时长，JSON 对象字符串）；
  - **`completed_tasks` / `pending_tasks` 数组项新增 `humanMs` / `agentMs` 字段**（该任务当日人工 / Agent 时长）；
  - `extra_work` 收窄为仅 `{ temporaryWork, meetings }`，`risks`、`tomorrow_plan` 拆分为独立输入变量。

## 步骤

### ① 创建或确认知识库空间

```bash
# 列出已有知识库空间（命令名以实际 help 为准，参考：dws wiki workspace list）
dws wiki workspace list

# 若没有可用的空间，创建新空间（参数以实际 help 为准，参考：dws wiki workspace create）
dws wiki workspace create --help
```

从返回中提取 **WS_ID**（空间 ID，具体字段名以实际返回为准，如 `id` / `workspace_id`）。

### ② 在知识库内创建「日报」文件夹

```bash
# 在目标空间下创建文件夹（命令名 / 参数以实际 help 为准）
dws wiki node create --type folder --workspace <WS_ID> --name 日报
```

从返回中提取 **FOLDER_ID**（文件夹节点 ID，如 `id` / `node_id`）。

### ③ 提取 WS_ID 与 FOLDER_ID

记录上两步实际返回中的两个 ID。**ID 一律来自命令返回，严禁编造**；建议先保存在本地草稿，供下一步写入 `.env`。

### ④ 写入 .env

在项目根目录 `.env`（已被 .gitignore 忽略，不会提交）中写入：

```env
DINGTALK_WIKI_WS_ID=<第①步提取的 WS_ID>
DINGTALK_WIKI_FOLDER_ID=<第②步提取的 FOLDER_ID>
PUBLISHER=dws
```

### ⑤ 启动校验

- 后端启动时若 `PUBLISHER=dws` 且 `DINGTALK_WIKI_WS_ID` 为空，会打印警告：
  `[prodash-server] [warn] PUBLISHER=dws 但 DINGTALK_WIKI_WS_ID 为空：创建日报文档会失败并标记 publish_failed ...`
  配置后此警告应消失。
- 可用 `dws drive list --workspace <WS_ID>` 验证 WS_ID 有效（能列出空间内内容即有效）。

### ⑥ 首次真实发布验证

1. 启动 MySQL + 后端：
   ```bash
   docker compose up -d
   npm run server
   ```
2. 手动触发生成（`date` 填当天）：
   ```bash
   curl.exe -X POST http://127.0.0.1:8787/api/reports/generate ^
     -H "Content-Type: application/json" ^
     -d "{\"date\":\"YYYY-MM-DD\"}"
   ```
   > Windows PowerShell 下 `curl` 是 `Invoke-WebRequest` 别名，请用 `curl.exe`。
3. 检查钉钉知识库「日报」板块：应出现「日报 YYYY-MM-DD」文档；report 状态为 `published`、`doc_url` 可打开。
4. **覆盖验证**：再次调用 generate → 同一文档被**更新覆盖**（nodeId 不变，`dws doc update`），而非新建文档。

## 注意事项

- **dws 二进制 shim 问题（Windows 演示机前置确认）**：若 dws 安装为 `.cmd` / `.bat` shim，`DwsCliPublisher` 用 `execFile` 直调可能报 `ENOENT`。此时需将 `DWS_BIN` 指向真实可执行文件（如 `.exe` 或包内真实 bin 路径），并在启动前确认。
- 发布失败时 report 停在 `publish_failed`，前端提供补发按钮；dws token 过期属 demo 接受风险，不自动刷新（决策清单 §五）。
